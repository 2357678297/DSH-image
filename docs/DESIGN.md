# 设计说明 · velapi-image-go

## 目标

在 dsh 窗口的**右侧**长出一个生图工作台：简约、规范、大圆角。参考稿是「左导航 +
中部对话 + 右栏卡片」的三段式，所以工作台本身就是那三段，接到哪一侧都成立。

两条硬约束来自 dsh 的插件模型，决定了后面所有取舍：

1. **宿主半边是一个进程内的 cordis 插件**——它注册路由，但拿不到任何浏览器状态；
2. **浏览器半边是一段在别人页面里跑的 bundle**——样式与上下文都得自持，宿主升级不能
   把界面打散。

## 三段式布局

```
┌─────────────────────────── API 对话生图工作台 ───────────────────────────┐
│  导航          工作区                                      检查器        │
│  对话生图      提示条 + 会话线程 + 输入区（工具条 / 计数 / 发送）  图片        │
│  图片管理      搜索 · 模型筛选 · 批量选择 · 平铺网格              信息        │
│  信息管理      列表 + 编辑弹窗                                   供应商      │
│  图片处理      工具条 + 画布（参数浮窗）+ 图层面板（框选 / 裁切 / 矫正 / 羽化 / 调整 / 图层…）│
│  供应商管理    运行期配置 + 供应商表 + 测试连接                              │
└──────────────────────────────────────────────────────────────────────────┘
```

- 宽屏（≥ 约 900px）：导航 150px + 工作区自适应 + 检查器 268px，和参考稿一致。
- 窄屏（右侧栏 / 停靠面板）：导航折成顶部段控件，检查器收进工作区下方，靠 `flex` +
  `min-width:0` 自适应，不写死断点的 px。
- `view=chat` 时才显示检查器：图库/信息/供应商三页已经是全宽工作区，再挤一列没意义；
  「图片处理」同理，它自己就是三栏（工具条 / 画布 / 图层，参数是一块压在画布上的浮窗）。

## 视觉 token

单文件 CSS 变量表，深浅两套，颜色语义而不是用途命名：

| token | 浅色 | 用途 |
| --- | --- | --- |
| `--vig-accent` | `#2f6bff` | 主操作、选中态、发送按钮 |
| `--vig-accent-soft` / `--vig-accent-line` | `#eaf2fe` / `#d7e5ff` | 提示条、导航选中底 |
| `--vig-line` / `--vig-line-strong` | `#eceef2` / `#e2e5ea` | 分割线、容器描边 |
| `--vig-text` / `--vig-text-muted` / `--vig-text-faint` | `#1b1f27` / `#8a9099` / `#a9aeb6` | 三级文字 |
| `--vig-r-card` / `--vig-r-tile` / `--vig-r-pill` | `18px` / `14px` / `999px` | **大圆角**：卡片 18、小卡 14、胶囊全圆 |
| `--vig-shadow` | 双层低透明阴影 | 只给浮层用，普通卡片只有 1px 描边 |

深色不是另画一套，而是 `body[data-ds-dark-theme]` 下重绑同一批变量——宿主切主题，
工作台跟着走。这也是唯一一处沾宿主的地方（属性选择器，不是私有 class）。

## 数据流

```
输入框 → POST /generate（立刻返回 job）→ 前端乐观插入一条 turn
                     ↓
       宿主排队（concurrency=3）→ 调上游 /images/generations → 下载图 → 写图库
                     ↓
       GET /job?id=… 每秒轮询（1.2s 起，逐步退避到 4s）→ 终态即停
                     ↓
       成功：渲染缩略图 + 操作（重绘 / 复制链接 / 下载）；同时刷新图库计数
```

- **不用 SSE/WebSocket**：一次生成 40~90s，轮询够用，省掉一条长连接的生命周期管理。
- **前端不做本地缓存**：图库、信息、供应商都从宿主读，多窗口打开时不会各说各话。
- **参考图走 base64 一次性投递**：宿主只把它塞进这一次请求，任务记录里会把
  `requestImage` 删掉，避免 `jobs.json` 里躺着一堆 base64。

## 关键取舍

**为什么是普通 HTTP 前缀路由，不是 `/api` RPC。**
`/api/*` 是 connection 的 RPC 面，未认领的端点返回 200 + 失败信封；路由匹配是「先精确、
再最长前缀、最后 fallback」。注册一条比 `/api` 更长的前缀既稳定胜出，又不用去声明
RPC 契约——这个插件的消费者只有自己的前端。

**为什么图要落盘。**
上游给的是 `jpgpng.velapi.cc` 上的临时 URL。图库要能离线翻、要能重命名、要能在
「用这张重绘」时拿回字节，所以生成成功即下载、嗅探真实格式（上游常回 JFIF 而不是
PNG）、写进 `library/files`，索引单独一份 `index.json`。

**为什么三个落点，而不是只挂右侧栏。**
产品右侧栏的席位 API（`sidebarRightTabs` + keyed 的 `sidebar.right.pane.tab`）是内部
契约，换版本可能变。所以右侧栏是首选落点，`shell.overlay` 的停靠面板是**不依赖侧栏
内部结构**的兜底，`settings.section` 是永远可用的保底入口。三者各自 try/catch，
任何一个挂掉都不会带走另外两个——`surfaces` 还能直接裁掉某个。

**为什么密钥写进 profile patch。**
桌面端有三种拉起方式（开始菜单、命令行、更新器），继承的环境变量并不一致。内联密钥
才不会看运气；运行期在「供应商管理」里改的值写进 `state/config.json`，优先级更高，
所以 patch 里那份只当出厂默认。

**入口长在右侧栏自己的「开始页」里。**右侧栏那片空白不是随便放的容器，它是 ui-sidebar-right 的 guide 页面：hero 圆环 +
一列卡片，卡片来自各插件在 tab 注册表里声明的 `guide[]`。所以入口的做法不是自己画一个
浮层，而是把「生图工作台」作为一张卡片交上去——视觉、点击行为、键盘快捷键都跟
「工作区文件 / 新建终端 / 浏览器」一致，样式跟着宿主主题走，宿主改版也不会错位。
只有一件事要记住：`register()` 的 `id` 必须同时用作面板内容与标题两个席位的 key，
`priority` 是档位字符串，`guide[]` 条目的 `order` 不能省（见 README 的契约小节）。

**为什么有个 `__internals` 导出。**
`tools/preview.mjs` 要用同一批组件渲染静态预览页——预览和线上是同一套像素，不是另画
一张图。宿主加载时不会碰这个字段。

**一个组件，三种容器宽度。**
工作台会被放进设置页整页（~1280px）、产品右侧栏分栏后的一栏（~400px）、停靠面板
（420px）。所以根节点用 `ResizeObserver` 量**自己容器的**宽度，低于 660px 切窄形态
（导航折成顶部段控件、检查器沉到底部、缩略图动作行换短文案），而不是看窗口宽度。
量尺寸用 `useLayoutEffect`：首帧就定形态。用 `useEffect` 会先在窄容器里画一帧三段式
再跳，那一帧依旧溢出被裁，看起来就是「渲染坏了」。

**为什么要有「溢出」这项检查。**
窄容器被裁过一次，病因是输入区那排 `<select>`：它是 `width:100%` 且 `min-width:auto`，
而 select 的最小内容宽度等于最长选项文字（`nano-banana-2.1` ≈ 120px），三个并排加
工具钮、计数、发送键 ≈ 500px，压不下去就把整列撑宽。光看截图只能看出「被裁了」，
看不出是谁干的，所以做了 `tools/fit-check.mjs`：把工作台塞进固定宽度的框里，用真
Chrome 量 `scrollWidth - clientWidth`。窄形态在 320→1280 全宽都必须是 0px。

**入口不许出现两次。**
三个落点是为了「宿主改版也不至于全灭」，不是说三个入口要一起摆在用户脸上。规则定成：
侧栏 tab 挂载 → 停靠面板整个不渲染；侧栏席位拿不到 → 才轮到停靠面板。停靠胶囊的位置也
从窗口右上角挪到右下角：右上角是宿主会话头部的展开按钮的地盘，撞上去就是两个同名按钮
叠在一起，看起来像 bug。同理，`sidebar.right.pane.tab.title` 那个席位不再注册——
它就是 tab 条上的标签本身，宿主自己会画。

**竖栏要像一条竖栏。**
侧栏会被拉满高度，一条只有四个导航项、下面全空的白柱子很难看。底部那块计数（图库 /
信息 / 任务）不是装饰，是把空出来的地方换成一眼能看到的东西，顺带把栏目重心压到底边。
窄形态里导航折成一行段控件，这块自动隐藏。

**同一件事只写一遍。**
第一版把「供应商 / 模型 / 密钥」抄在了四个地方：工作台头部一颗 `velapi` 胶囊、工作区头部
一颗密钥胶囊、检查器供应商卡里又一颗密钥 + 一个「供应商管理」跳转、侧栏底部再来一遍。
四个地方说的是同一句话，用户一眼看到的就是「一个供应商显示太多了」。定成归属表：

| 事实 | 唯一归属地 |
|---|---|
| 密钥 / 连接状态 | 工作区头部胶囊 |
| 当前供应商 | 检查器「供应商」卡的下拉框 |
| 模型 / 尺寸 / 张数 | 输入区选择器 |
| 图库 / 信息 / 任务计数 | 侧栏底部（窄形态隐藏） |
| 队列 / 服务端异常 | 真有事才出声 |
| 「供应商管理」 | 左侧导航项 |

侧栏底部也因此从「供应商/模型/密钥」换成计数——它填的是空白，不是第二个状态栏。

**规格统一：一次修掉「按钮没有内边距」这类系统性问题。**
样式重置原来写成 `.vig-root button{padding:0;border:0;background:none}`，特异性 (0,1,1)，
压过了 `.vig-btn` / `.vig-mini` / `.vig-nav-item` 这些 (0,1,0) 的组件规则——于是全插件的按钮
内边距和边框一直是死的：供应商页的「保存」是个窄蓝块、文字顶出边框，次要按钮连框都没有。
改成 `.vig-root :where(button){…}`（`:where()` 贡献 0 特异性）后组件规则才真正生效。
测试里加了闸门防止改回去。

**供应商管理：表格换成一行一卡。**
四列表格在 420px 的侧栏里必炸，而且「模型」那列显示的是 `22`（数组长度），毫无信息。
改成一供应商一卡：名称 +「当前」标记 / 接口地址 / `密钥 … · 模型 nano-banana-pro 等 3 个 · 备注 …`，
动作统一收成小号按钮（设为当前 / 拉取模型 / 编辑 / 删除），删除用危险色。
模型摘要显示第一个模型名 + 个数，没拉取过就说「未拉取」。

**表单页居中收窄。**
宽面板（1000px+）里把输入框拉成一条长条很难看，所以表单类页面套 `.vig-page`
（`max-width:760px` 居中），字段用 `.vig-form-grid` 两列，窄形态自动塌成单列；
图库那种图墙照旧满宽。运行期配置的初值直接取自配置，不再靠 `useEffect` 回填
（否则首帧是空输入框，SSR 更是整片空白）。

**模型列表：先分类，再按需展开。**
模型目录是二十多条平铺 id，原生 `<select>` 会把它摊成一张没有结构的长菜单。改成：
按钮态只显示当前模型，点开才渲染三层结构（能力 → 名字前缀族 → 模型）。

分类按**中转站给的元数据**，不按名字猜：`GET /v1/models` 每条带 `image_family` /
`video_family`，其中的 `kind` 是权威值；宿主收成 `modelMeta` 挂在供应商记录上再给前端。
踩过的坑：`omni-flash` 被靠名字归成「对话」，实际 family 写的是 `video`（`r2v / t2v`，8 秒）。
名字前缀表只在元数据缺失时兜底，且「认不出来」就叫「其它」，不再硬说成「对话」。

前缀 = 去掉版本号与变体后缀（`nano-banana-2.1` / `nano-banana-pro` → `nano-banana`；
`veo_3_1_r2v_fast_ultra_relaxed_8s` → `veo`），族按条数多的排前面，顶部带过滤框。
目录里 `enabled:false` 的（本账号是 `imagen-4*`）照样列出来，但淡显 + 标「未开通」。
尺寸/张数这种三五个选项的下拉继续用原生 `<select>`。

弹层落点：输入区往上弹贴右，图库筛选往下弹贴左；窄容器里把定位包含块从按钮提到
输入区/工具条，宽度铺满卡片 —— 否则 236px 的弹层会从 300px 的卡片里伸出去被
`overflow:hidden` 裁掉。`tools/fit-check.mjs` 现在顺手量这条：弹层必须完全落在卡片内。

**预设卡：右栏第一张卡从「空 textarea」换成卡片墙。**
原来那是「信息」输入框 + 「插入输入框」按钮：只把一段文字搬进输入框，参考图还得自己去图库里找。
换成一张卡 = 参考图封面 + 标题 + 提示词摘要 + 标签 + 动作，点一下就把提示词与参考图一起套上。

- 卡片给的是**参考图**（img2img 的输入），不是展示图；所以编辑里三个入口：上传 / 图库挑 / 移除。
- 封面加载失败退回「无参考图」占位 —— 参考图是外部资源，坏了不该让整张卡看起来像 bug。
- 网格 `grid-auto-rows:minmax(0,1fr)`：同一行的卡等高，标签换行不会把按钮顶得高低不齐。
- 底部三动作：`用这张`（占满剩余宽度，`white-space:nowrap`）、编辑、删除（都是图标 + `aria-label`）。
  踩过的坑：三个带文字的按钮挤在 118px 的卡里，「用这张」被压成竖排三个字。
- 内置卡随包带 4 张 256×256 参考图（`assets/presets/`），走 `/preset/<file>` 提供，文件名过白名单。

**图片处理工具箱：生成出来的图不用离开工作台就能改。**
左导航原本止于「供应商管理」，中间只出不改：想出竖版、想去掉多余留白、想羽化一张贴纸，
都得先下载、拿别的软件改、再当参考图传回来。所以第四项是整页的 PS 式工具箱。

- **左工具条 / 中画布 / 右参数**三栏（`96px / 1fr / 236px`）。窄容器折成一栏，工具横排折行
  ——不这样 300px 的卡片里画布只剩几十像素。
- **纯前端实现**：所有动作是 canvas 上的纯函数（`psRotate` / `psStraighten` / `psCrop` /
  `psFeather` / `psCanvasSize` / `psSlice` …），不新增任何宿主端点，改这块不用重启应用。
- **原图不动**：历史里存的是「原图 + 一串动作之后的画面」，`还原这张` 直接回原始 img；
  撤销/重做只保留最多 12 份快照，并且只在需要导出时才 `toDataURL`，避免大图把内存吃满。
- **出口复用已有链路**：`设为参考图` 就是把它转 dataURL 走 `/upload` 落盘再挂到输入区，
  和预设卡、图库走同一条路；另外给一个本地 `下载`。
- **矫正不是「看着差不多」**：把画面按候选角度转一遍，按行统计墨点数、取相邻行落差平方和最大的
  角度（双线性采样 + 全图均值二值化，明暗底都吃得下），再按同比例最大内接矩形裁掉斜边
  ——裁完取景比例不变，只是四角被切掉。
- **手动矫正是「标尺」，不是「滑块 + 应用」**：照 PS 的标尺/拉直做 —— 在图上按下、沿一条本该
  水平（或竖直）的边拖一条线，`psRulerAngle(from, to)` 给出该转的角度（比 45° 陡就按竖直对齐，
  拖太短返回 null 不算数），拖的过程中底图用**一个 CSS transform** 跟着转（不重画像素，
  所以是真·实时），第二层 canvas 画参考线、端点十字和「裁完还剩多少」的暗角框；松手立刻
  `psStraighten` 提交，没有「应用」按钮。Esc 撤掉这次拖拽。滑块那套等于让用户先在脑子里
  量角度再输数字，和鼠标直接指是两回事。自动估角保留成一个按钮（不拖也能用）。
  纯函数拆开之后：角度对不对是 `psRulerAngle` 的用例，转过之后平不平是 `psStraighten` 的用例。
- 羽化用蒙版扣 alpha：蒙版边界压在选区线上，模糊半径取 `r/2.4`，于是边缘正好半透明、
  往里约 `r` 像素回到实心（和 PS 的手感对齐）。
- **要看细节就得能放大**：滚轮以光标为锚点缩放（`psZoomAt` 把滚动位置按比例补回，光标底下那点
  不动），范围 5% ~ 800%，右下角一条比例条给 `− / + / 适应窗口 / 1:1`。大图按适应窗口显示只有
  几十像素宽，没有这一步等于看不清。放大后中键拖动平移，滚动容器用 `flex + margin:auto`
  居中（`justify-content:center` 会把左上角的溢出截掉，滚不到）。
- **挂载 ≠ 看得见（「重启后按键又不见了」的病根）**：工作台的主落点是右侧栏的一个 tab，
  而 tab 类型注册时写了 `keepMounted: true` —— 宿主为了切 tab 不丢状态，会把非激活的 tab
  一直挂着，只用 `display:none` 藏着。旧代码只看「侧栏面板挂载了没有」（`rightbarPaneMounted`），
  挂载就把它自己的右下角入口胶囊收起来。于是右侧栏停在别的 tab（重启后默认回到开始页）时：
  工作台在 DOM 里、却看不见，胶囊又被自己收掉 —— 整个插件一个入口都不剩。
  现在分开广播 `mounted` / `visible` / `onScreen`：可见性按几何量判（`getClientRects()` 非空 + 尺寸 > 0 +
  `visibility !== hidden`），`IntersectionObserver` / `ResizeObserver` / `resize` / 一秒一次的复量
  只当「重新量一次」的触发器（目标一开始就挂在 `display:none` 里时观察者可能根本不投递更新，
  拿它当唯一判据会卡死在「看不见」）。判定收在一处纯函数 `dockFace({paneMounted, paneVisible, paneOnScreen, open})`：
  **只有 `onScreen` 认过才让位**（观察者首次投递前给 800ms 宽限，之后只认它的判断），
  其余情况收起给胶囊、开着给面板 —— 宁可多一个胶囊。
  这条有真浏览器闸门 `tools/dock-check.mjs`：真 `PaneHost` 挂进 `display:none` 宿主 → 必须报
  `mounted:true, visible:false`；再把它显示出来 → 必须翻回 `visible:true`；隐藏态 + 收起 →
  真 DOM 里必须出现 `button.vig-dock-launch`；把宿主摆到视口外（几何量正常、其实没在屏幕上）→
  `onScreen:false` 且入口照样露。
- **落点注册失败不能只在 console 里沉掉**：三个落点各自 try/catch，以前失败只 `console.warn`，
  界面就凭空消失（用户和我都只能猜）。现在失败的席位与原因攒进 `window.__velapiImageGo.errors`，
  连注册结果 `surfaces`、侧栏状态 `paneState()` 一起挂出去，控制台一行就能定位。
- **桌面端刷新这件事，得先看清楚宿主怎么做的**：产品是 Electron（`dsh-app://app`），
  `Ctrl+R` 没人接、菜单里也没有「重新加载」，只在 `before-input-event` 上挂了 F12 → `openDevTools`。
  但插件客户端本来就是热的：宿主盯着每个包的入口产物，一变就通过 `/plugins/events` 推
  `{"type":"rebuilt","id":…,"rev":…}`，页面里的 `client-hmr` 收到就 `entries.reload(id, rev)`
  —— 改完 `client.js` 存盘，界面自己换新版本，不需要任何按键。所以「怎么刷新」在面板上留了一颗
  电源图标（`reloadShell()` → `location.reload()`）当页面级兜底：缓存、半挂的席位、断掉的事件流，
  重载一次全清。宿主半边不在这条通道上（改 `lib/index.js` 要重启应用），排障时别把两件事混起来。
- **四点矫正：三种「畸变」其实是一件事**：`四点畸变`（拖取图四点、拉平成正矩形）、
  `自由拉伸`（源、目标各四点）、`变形`（取图四点固定是整图四角，只拖目标四点，PS 的「扭曲」）——
  用户要的是三种手感，数学只有一套：八个角点解一个 3×3 单应矩阵（8 元线性方程组，高斯消元 +
  部分主元），输出画布逐像素反查源图（沿行递推分子/分母，省掉每像素的乘法；双线性采样；
  查不到的地方留透明）。输出尺寸分两路：畸变的目标是自动算出的正矩形（对边取平均），
  自由拉伸/变形的输出贴目标四点的外接矩形（四边形之外透明）。四点初值一律取图片最外圈
  （`psQuadCorners`，用户原话「宽长应该到图片最外边」），所以一进工具读数就是整图尺寸。
  退化输入在解方程那步就返回 `null`：三点共线、四点重合，以及**四点凹进去 / 交叉**——
  后者是算得出来但一定错的（单应矩阵会把画面翻到四边形外面，屏幕上是一团镜像），
  `psQuadConvex` 直接判死，面板读数换成说明书式的提示，不给糊图。
- **拖动是实时的，没有「应用」这一步**（用户原话「移动需要实时，不通过应用后」）：
  `pointermove` 改四点 → 计划重算 → 结果重画，回车 / 换工具 / 换图才落定（`bakeWarp`）。
  为了跟得动指针，拖动途中不重画全分辨率：`psWarpPreview` 把「输出缩放」和「源图降采样」
  两级缩放合成进采样矩阵 `H = S(q) ∘ inverse ∘ S(1/k)`（源图降到 1024px 缓存成代理，
  输出封顶 720px），松手再按屏幕比例补一张清晰的。
- **实时结果就画在主画布上，不另开小窗口**（用户原话「实时小窗口不要，直接在画布实时才对」）：
  `原图` 这一侧先把原图铺满，再把结果按**蓝四点的外接矩形**贴回去、并用蓝四点路径 `clip()` ——
  框里当场被拉平 / 拉成形状，框外一个像素都不动；`结果` 这一侧干脆整张画布就是结果。
  曾经在面板里挂过一张「实时」小图，被用户否掉了：同一份信息摆两处，眼睛还得来回对。
- **「原图」/「结果」是两个视图，不是两张画布叠一起**：单应矩阵把取图四点映到目标四点上，
  在输出空间里这两组点必然重合，一张图上画不出来。于是主画布在 `src` 视图显示原图 + 蓝四点
  （取图，摆位置）＋框内实时结果，在 `dst` 视图显示实时结果 + 橙四点（目标，拖形状）。
  结果视图按屏幕比例出图并 1:1 摆放（`cssPerPx = warpStageView ? 1 : scale`），所以两侧看上去一样大。
- **四点矫正的预览与真画布得走同一套几何**：真跑起来画在第二层 canvas 上（`is-warp` 光标 +
  编号方手柄），但静态预览/SSR 里没有真 canvas，于是同一条几何再画一遍成 SVG（`initial.warp` 当种子）。
  读数也不再要求真 canvas —— `psWarpPlan` 只吃宽高，所以截图里就能看到「输出 223 × 178」这种真实数字，
  而不是一句占位提示。真机闸门 `tools/warp-check.mjs`（39 项）：造「梯形 + 四角色块」的图量拉平后的
  尺寸与四角颜色、量「原图 (5,5) 是白的 → 拉平之后同一位置必须是内容」；再挂真 `PsView` 验
  「进工具四点贴最外圈、拖到一半（`pointerup` 之前）读数就变了、画布里框住那块已经按新计划重采样过
  （合成图底是渐变 + 8px 细条纹：与期望像素误差 ≤3，与未重采样的原图差 100，框外差 0）、松开不回弹、
  面板里没有小窗口、
  点空白不误触、Esc 撤回、参数栏里没有『应用』按钮、切「结果」侧画布就是拉平后的尺寸、
  切走工具自动落定且撤销从禁用变可用、变形方式拖橙四点真的把画面拉走、凹四边形判死」。
- **提示只有一个出处**：提示容器 `.vig-toasts` 只由外壳 `Workbench`（`useToasts`）渲染，
  `PsView` 是独立组件，提示得走注入的 `actions.toast`。之前 `PsView` 里直接调全局 `toast(...)`，
  浏览器里就是 `ReferenceError: toast is not defined` —— 画面照改（`commit` 在前），但「已矫正 3°」
  这类反馈一条都出不来；这种错只有真浏览器跑一遍才看得见（SSR 测试不执行事件处理器）。
  现在收敛成 `const notify = actions?.toast ?? (() => {})`，并加了一条「PsView 里不许出现裸
  `toast(`」的静态断言。这条是 `tools/ruler-check.mjs` 抓出来的。
- **拖拽这种事得用真事件验**：纯函数测得到角度、测不到「拖着的时候画面在不在转」。所以
  `tools/ruler-check.mjs` 把真 `PsView` 挂进真 Chrome（react-dom/client + 一个极小的 CJS 模块表），
  在真画布上派 `pointerdown → pointermove → pointerup`，断言：拖动过程中底图的 `transform` 已经变了、
  参数栏读数跟着跳、第二层 canvas 的暗角框有像素、松手后工具栏里的尺寸真的变小。
  顺带发现 `setPointerCapture` 在合成事件里会抛 `NotFoundError`，包了一层 `psCapturePointer`。
- **线宽和手柄跟着缩放折算**：选框边框、切割线、手柄判定半径都按比例反算，屏幕上永远是 1.4px /
  10px，缩小时不会缩没、放大时不会糊成大块。
- **操作区域按需长大**：侧栏里的工作台只有几百像素宽，三栏固定占掉 96 + 236 之后画布就剩一条。
  所以工具条能收成 52px 图标栏、参数浮窗能收成一条竖签；`data-labels` 切换工具条列宽，
  参数浮窗不再占列（`vig-ps-float` 压在画布上），右边那列留给图层。工具栏的
  「专注画布」和 `\` 一次收两侧。画布高度用 `clamp(320px, 58vh, 720px)` 跟窗口走，
  在 950px 高的窗口里比原来高出一倍多。收起状态进 localStorage，默认展开（同停靠面板：
  更新换端口会清 origin，默认收起就等于「功能失踪」）。
- **快捷键照 PS 的肌肉记忆排**：字母切工具（`V/C/S/R/L/W/N/F/Z/M/U`），`Ctrl+Z` 撤销、`Ctrl+0/1`
  适应与 1:1、`+/-` 缩放、`\` 专注、`?` 打开快捷键表。键位映射抽成纯函数：`psCombo(event)`
  把事件归一成 `"ctrl+shift+z"`，`psLookup(overrides)` 给出「组合串 → 动作」的表，`psShortcut`
  只做一次查表。所以「哪个键干哪件事」「自定义之后旧键失效」都能离线逐条断言，不用开浏览器。
- **键位是数据，不是散在代码里的 if**：动作表 `PS_ACTIONS`（24 条：11 个工具 + 视图 / 编辑 / 出口）与默认键位表
  `PS_DEFAULT_BINDINGS` 分开，用户改过的只存差异（`{"tool.select":"alt+1"}`），以后默认键位改了
  照样吃到新的。一个动作允许多个键位（逗号分隔），所以 `+/=`、`Esc/Del` 这类「同一个意思两种按法」
  不必写特例。录制态用 `psConflict()` 查重 —— 撞键当场报「已被谁占用」，不静默覆盖。
  落盘落两处：localStorage 立刻生效、离线可用；宿主 `config.json.shortcuts` 跨更新
  （换端口会清 origin 的 localStorage，这一层是「插件又不见了」那次的教训）。宿主老版本会忽略
  这个字段，客户端 `.catch` 后只用本地那份，不会因为宿主没跟上就崩。
  输入框/下拉里打字时不拦键（否则在宽高输入框里按 `C` 会跳到裁切），但 `Esc`、`Enter` 这类
  「退出 / 确认」语义的键仍旧生效。
- **空画面要占满**：没图时 `.vig-ps-empty` 绝对定位铺满整块画布、内容垂直居中，里面摆
  「最近生成」（图库最近 24 张）与「预设样张」（8 张预设卡的图），点一下就 `loadAsset()` 进画布；
  两块都没有才退化成三步说明。截图里红框圈出的那块空档就是这里，不能留白。
- **分辨率是文件头里的真数据**：画布面板的 DPI 导出时写进 PNG 的 `pHYs`（像素/米，块 CRC 重算）
  或 JPEG 的 `JFIF` 密度；`设为参考图`、`下载` 都带。base64 编解码和 CRC32 都是自己的实现，
  所以这段逻辑浏览器里跑得动、Node 沙箱里也测得动（不依赖 `btoa` / canvas）。
- 底图与选框分两层 canvas：底图只在换图/改图时重画，拖动选区只重画选框层。
- 预览静态页里跑不了 effect，`PsView` 支持一个 `initial.preview` 分支：渲染成 `<img>` +
  DOM 伪选框（复用同一套手柄几何），这样 `ps.png` / `ps-canvas.png` / `ps-zoom.png` /
  `ps-dock.png` 能反映真实排版。`initial.collapsed` / `initial.keys` / `initial.bindings` /
  `initial: null`（空画面）也是同一个用途：把「收起态、快捷键表、自定义键位、空态」也截成图。

## 图层与调整

「图片处理」不只做几何：生成出来的图经常还要调色、叠贴纸/文字、只改其中一块。所以工具箱补了
「调整」（`U`，四段：调整 / 曲线 / 色阶 / 滤镜）和图层（7 种叠加 + 每层蒙版 + 单层编辑）。
这一节只记三条设计取舍。

**蒙版用 alpha + `destination-in`，不另存一份 RGB 蒙版图。**
蒙版的语义只有一句话：「这一层的每个像素露出多少」——那就是 alpha。所以蒙版是只让 alpha 带信息
的画布（RGB 全白），覆盖率由 `psMaskAlpha(width, height, selection)` 这类纯数组函数算
（选区里 255、框外 0；没有选区就整张 255），合成时把图层画到临时画布，再用画布原生的
`globalCompositeOperation = "destination-in"` 把蒙版乘上去（dest = dest × src.alpha）。理由：

- **不手写逐像素乘法**：浏览器自带的合成路径已经处理了预乘 alpha 与半透明，
  手写一套既容易错，又把开销压在 JS 循环上；`psMaskedCanvas` 只负责「画图层、换算子、画蒙版」。
- **蒙版可以白拿**：羽化、选区、以后要加的渐变蒙版都只是在同一条 alpha 通道上做文章，
  合成代码不用改；反转也只是 `255 - a`（`psInvertAlpha`），不需要第二张图。
- **蒙版和图层解耦**：`psLayerCommit` 写回时只换 `canvas`，蒙版对象原样保留 ——「改这层的内容」
  和「改这层露多少」是两件事。

**曲线先算 LUT，而不是每个像素现插值。**
一条曲线本质是 256 个输入值到 256 个输出值的映射。先把控制点插值成
`Uint8ClampedArray(256)`（`psCurveLut`：点之间线性插值、两端保持端点值），再逐像素查表
（`psApplyLutPixels`）。理由：

- **复杂度从「像素数 × 控制点数」降到「256 × 控制点数 + 像素数」**：一张 3000×4000 的图
  省掉数千万次比较。
- **编辑器和应用共用同一张 LUT**：曲线面板画的那条 `polyline` 就是 `psCurveLut` 的输出，
  屏幕上看到的形状就是点「应用曲线」之后的结果，不存在「预览近似、应用精确」两套实现。
- **和色阶 / 反相共用出口**：`psLevelsLut` 与反相也都是 256 项表，`psApplyLutPixels(data, lutR,
  lutG, lutB)` 支持三通道各一张表；以后加通道曲线不用再开一条代码路径。
- **纯数据、Node 可测**：恒等曲线不改任何值、端点被拉到端点、S 曲线压暗部提亮部，都是离线断言。

**单层编辑复用整套工具管线，不另写一套「图层内工具」。**
点图层行进入编辑会话时，做法是把这一层的 canvas 当成普通 `source` 装进 `PsView`（和打开一张图
同一条 `loadImage` 路径），底图存进会话；所有工具、历史栈、快捷键、参数浮窗原样作用。进入 / 退出
的纯逻辑收在 `psLayerSessionStart` / `psLayerSessionExit`（后者内部用 `psLayerCommit` 把当前画布
写回该层，再还原底图）；连点两下同一层 / 连点两下「回到合成」都有会话锁挡掉。理由：

- **工具只有一套**：裁切、旋转、矫正、羽化、调整、曲线、滤镜在「改整张图」和「改一层」时行为
  完全一致，不会出现「图层里能裁不能转」这种缺口。
- **撤销天然可用**：会话期间的历史栈就是普通图片编辑的历史栈，不用为图层编辑再造一层撤销。
- **写回只换 `canvas`**：蒙版 / 叠加算法 / 不透明度 / 名字都保留 —— 编辑内容不该重置显示参数。
- **代价是有意的**：编辑一层时看不到别的层，合成结果在退出会话时立刻可见；这比一边改一边猜
  叠加效果更可控。

配套的几处实现选择：

- **7 种叠加算法直接用画布合成算子**（`source-over / multiply / screen / overlay / darken /
  lighten / lighter`），不手写公式 —— 理由和蒙版相同；`psDrawLayers` 只负责按顺序、可见性、
  不透明度画，认不出的算法回落「正常」。
- **导出走合成**：`下载` / `设为参考图` 在有图层时先 `psLayerExport(底图, layers, w, h)` 再导出，
  保证「看到的就是存下来的」；否则叠加算法调了半天，导出的还是底图。
- **参数改成浮窗、原位让给图层**：参数是「当前工具的选项」，用完就收；图层是「一直要看的
  东西」。所以参数浮在工具箱上（默认左上角，可收起），固定列让给图层；窄容器里三栏折成
  一栏，参数仍浮着，不再把画布挤成一条。浮窗位置可以拖（按住头部，位置写进
  localStorage；窄容器里自动贴右上，不按绝对 left 往外顶）。
- **几何变换联动图层**：裁切 / 旋转 / 拉直 / 缩放 / 改画布 / 翻转 / 四点透视提交时，`psTransformLayers`
  用同一套画布算子把每层画布和蒙版 alpha 一起变换（alpha 从底图坐标系重算，长度等于新尺寸）；
  图层尺寸和底图不一致时先重铺再变换，不裁掉内容。四点透视走同一份 plan.inverse 变形图层与蒙版
  （`psWarpGeometrySize` / `psWarpAlpha`）。否则「裁了底图、图层还挂在原位」这种错位会一路带到导出。
- **历史快照带图层**：`psHistorySnapshot` 存 `{name, canvas, layers, layerSession}`，撤销/重做
  把底图、图层、会话状态一起还原；只有 `canvas` 的旧快照走 `psHistoryRestore` 时容错，
  不会把图层清成 undefined。
- **图层的结构操作不进撤销栈**：撤销管的是当前画布上的像素与工具操作；加/删图层、调顺序、
  改叠加算法、改不透明度、加删蒙版都是即时生效的显示参数，不单独产生历史项（它们会被
  下一次底图提交的快照带走，撤销回到快照时刻的图层状态）。这是故意把「改内容」和
  「改显示」分开 —— 代价是这些操作误点后要手动改回来。

## 入口可见性：四处不变量
一次「重启后入口不见了」的报障，后来复发过一次，最后落成四条不许破的规矩：

1. **「拿不到」和「抛异常」是两回事**。第二次复发就栽在这里：新版 DSH 的 cordis 在服务还没注册时
   `ctx.get(name)` 会**抛**（`cannot get property "sidebarRightTabs" without inject`），而不是返回
   `undefined`；而 `immediately: true` 让本插件激活得更早，那一抛正好落在登记的第一步 ——
   异常逃出去，`if` 块直接跳 `catch`，**后面「等 `ctx.inject` 到货」那条路根本没走到**。
   所以规矩是：**每一次服务访问都包 try/catch**，失败只当「还没到货」，然后
   `ctx.inject(["sidebarRightTabs"], …)` 等它，**外加一层有界重试**（0.5s 起翻倍、最多 8 次）
   兜住「inject 回调没被接上」。探针被拒的原文与尝试次数随回执落盘。
2. **席位要等，不能一次性问**。右侧栏那个席位不是常驻服务：`ui-sidebar-right` 自己要等
   `slots / layout / locale / resources / sessions / uiSession / shortcuts` 七个服务才激活，
   而本插件只等 `slots`，激活得比它早。一次性 `ctx.get("sidebarRightTabs")` 在冷启动时
   必然拿不到；旧代码此时静默跳过，tab 类型与开始页那张卡一起没登记 —— 右侧栏
   重启后停在开始页，界面上一个入口都没有。改成 `ctx.inject(["sidebarRightTabs"], …)`：
   `register` 不可逆、也没人会替我们重建，所以「等它到货再登记」是唯一正确的做法。
3. **判据要悲观，不能乐观**。`keepMounted` 的 tab 一直挂着，`mounted && visible` 是宿主说了算的
   几何量：过渡动画、视口外、被别的层盖住时它都会说谎，而说谎的代价是停靠面板与入口胶囊
   同时让位。所以加第三路 `onScreen`（IntersectionObserver 认过才算），并且**未确认时一律
   当成「没在屏幕上」**：最多多一个入口胶囊，绝不出现「一个入口都没有」。
4. **失败要留痕，不能靠猜**。页面里发生的事宿主看不到，所以浏览器半边把落点结果、
   `sidebarRightTabs` 到没到、探针被拒的原文、尝试次数、面板三态、页面实况（胶囊/面板/席位/
   开始页卡片的 DOM 命中数）发回 `POST /client-report` 落盘。入口再丢，看文件就知道卡在哪一环。

## 上游报错与端点协议：两处「不要替用户总结」

1. **报错不翻译，原样摆出来**。中转站在失败时会给一句自己的总结（「生成请求失败，
   请查看具体上游错误」），把它当错误信息展示等于什么都没说。所以宿主在 `callUpstream`
   失败时挂 `error.detail`（`kind / method / url / status / statusText / code / model / body`），
   随任务落成 `job.errorDetail`；界面**只在失败的那条气泡里摆一张卡**：状态 chip、实际请求地址、
   响应体原文，外加「用这条提示词重试」与「复制报错」（复制的就是屏幕上那一份）。
   **有证据才摆证据**：没有 `errorDetail` 的老任务只占一行 —— 空请求行、「上游没给响应体」
   这种为了凑格式而生的行，比没有更糟。超时、连不上（`cause`）、
   下载失败、非 JSON、返回里没有图片字段各自有 `kind` —— 不同故障给出不同的证据，而不是同一句
   「失败了」。老任务没有 `errorDetail` 也不装样子：直说「上游没给响应体」。
   **输入框那一行只放参数，不放报错**：那里是选模型 / 尺寸 / 张数 / 协议的地方，报错塞进去会把
   参数挤走，而且同一条错误在两处出现就是「一个事实两个家」。
2. **协议跟每次生成走，不跟供应商绑定**。协议选择住在「对话生图」输入框那一行
   （模型 / 尺寸 / 张数后面），落进 `config.defaultEndpoint`；供应商那条记录只负责
   地址 / 密钥 / 模型 —— 换路由是「这次怎么生成」的事，不是「这个中转站是谁」的事。
   取舍顺序：请求里写的 > 那一行选的 > 供应商记录 > 自动检测；「自动检测」是缺省值，
   不压过上层任何更明确的选择（否则行里选了「图片编辑」会被记录里的 auto 静默吃掉）。
   协议表由宿主 `/status` 下发（`protocols`），界面只做兜底，两边 id 必须一致 ——
   宿主测试卡着这条不变量，因为一旦漂移，用户在下拉里选的协议会静默失效。
   下拉显示短名，title 挂全名与路由（长名会把窄栏那一行撑开，fit-check 量着）。
3. **视频这条链不假装出片**。`POST /v1/videos/generations` 返回的是任务体（各家中转站字段不一致），
   所以原样收进 `job.video.payload`，能认出地址就给链接、认不出就摆原始响应 + 一句「上游返回的是任务体」。
4. **参考图只有一条入口，三条来路**。粘贴 / 拖拽 / 「+」上传最后都调同一个 `attachReference`
   （读 dataURL → 存一份到 `uploads/` → 挂成参考图 → 回执），没有第二套逻辑要维护。
   粘贴的判定抽成纯函数 `pickClipboardImage(clipboardData)`（`items` 优先、老浏览器看 `files`、
   纯文字返回 `null`），配三条不变量：
   - **监听挂在工作区根上**，不是只挂在输入框上 —— 焦点停在模型 / 尺寸下拉里也得粘得上；
   - **纯文字不拦**：拿不到图片直接 return，不 `preventDefault`（把文字粘贴拦掉比不支持粘图更烦人）；
   - **通用文件名要换掉**：`image.png` / `blob` 这类截图名换成 `粘贴的图片-<时间>.png`，
     否则图库里一堆同名图分不清谁是谁。
   挂上之后是输入框上方**一张小矩形卡**（54×54 + 右上角小「×」）：不写文件名、不写状态，
   名字进 `title` —— 参考图是「我选了哪张」，不是「它叫什么」，通栏那版在窄栏里能占掉一整行。
5. **一轮对话两条**。记录里每轮都是「我发出去的那句话」（靠右、蓝色「我」头像）+「工作台的回复」（靠左）。
   以前只渲染回复 —— 翻记录时看不出当时让它做了什么，提示词只活在输入框里；而提示词本来就是任务的一部分。
   用的是任务的 `prompt`（入站就落盘的那个字段），刷新、翻历史都在；没有提示词的记录不会冒出空气泡。
6. **提示条贴窗口额头**。`ToastHost` 是 `position:fixed` 到视口顶端居中的胶囊，内容两侧各留三字白；
   成功浅蓝描边、失败红描边加浅红底。以前是贴着容器底部的通栏横条，在右侧栏 / 停靠面板里会被拉成
   一整行 —— 提示读起来像报错页。

7. **界面不能比宿主更笨**。宿主加新配置字段、界面先用上，这在插件里是常态（宿主那半边要重启才吃到）。
   所以保存配置一律**乐观更新 + 合并回包**：`{...previous, ...patch}` 先落本地，回包再合并，
   宿主不认识的字段缺失时保留本地值（`localStorage` 再留一份兜刷新）。
   反面教材就是「协议选不动」那次：`setConfig(payload.config)` 直接覆盖，老宿主把字段丢掉，
   用户刚选的值被回包冲回默认 —— 看起来像下拉坏了，其实是保存路径把选择吃了。
8. **落盘不许把宿主带崩**。`writeJsonAtomic` 在 Windows 上会被外部句柄挡下来（rename 覆盖已存在文件
   抛 `EPERM / EBUSY / EACCES`）。三件事一起做：同一文件串行排队、退避重试四次、失败清临时文件；
   而 fire-and-forget 的那次落盘（`enqueue()` 里入队先存一份）必须 `.catch()` 打日志 ——
   一次抖动变成一个未处理的 rejection，代价是整个宿主进程。这条是被测试逼出来的：
   宿主用例连跑多遍时偶发整段崩掉，追下去就是这里。
9. **任务状态要有人接着问**。轮询只挂在「我刚点的那次」上，刷新一次就没人管了 ——
   宿主早跑完，界面还停在「生成中…」。所以 `reload()` 会把还挂在 `queued / running` 的任务
   重新交给轮询，单条轮询再加 6 分钟上限：到点标 **状态未更新**（带原因与「刷新」按钮），
   不再无限转圈；宿主启动时也会把上个进程留下的 pending 任务标成 `interrupted`。
   参考图缩略图同一道理：宿主只存本站 `upload / asset` URL（`job.referenceUrl`），
   原始 base64 不进历史 —— 但「我这条消息带着哪张图」必须留得下来。
10. **模型属于谁就打到谁那儿**。一条供应商链 = 一个 baseUrl + 一把 key + 一份模型目录，
   模型必须打到拥有它的那条链。以前只看「请求里点名了谁 / 谁是当前供应商」，于是两台中转站
   分工时选路靠猜：grok（`api.velapi.cc`）和 GPT（`gank.velapi.cc`）都配上了，模型选了
   GPT 的 `gpt-image-2.5-c`、当前供应商还停在 grok，请求就打到 grok 的 baseUrl，回
   503 `No available channel for model gpt-image-2.5-c under group grok`。
   现在宿主的 `providerForModel(model, providerId)` 与界面同一套规则：**目录里有它的供应商优先**
   （点名/当前供应商的目录里就有它或还没拉过目录 → 用它；否则找拥有它的那条；都没有才回落）。
   界面同时做两件事：模型下拉每条标出归属（`GPT` / `grok`），选中模型顺手把「当前供应商」
   切到它所属那条；生成与「用这条提示词重试」都按模型重挑（老任务记错的 providerId 不照抄）。
   测试用两条假上游钉死：点名 A 但模型属于 B → 请求必须出现在 B 的命中记录里、A 一条都没有。
11. **key 和接口地址必须是一家**。密钥是站发的，一个站只认自己的 key；拿 A 站的 key 去问 B 站，
   B 站只会回 `401 invalid access key` —— 而各家 key 长得一模一样（都是 `sk-…`），从界面上
   看不出问题。所以三件事：
   - **编辑不抹 key**：弹窗里密钥框不回显明文，**留空 = 不改**（以前把空串当新值写进去，
     改个接口地址就顺手把 key 清了）；要换成运行期密钥得显式 `useRuntimeKey: true`。
   - **401 时说人话**：`explainKeyMismatch()` 拿这把 key 去问**本地已经配置过的**其它 baseUrl
     （不碰没配过的站、每家 20s 封顶），谁认它就返回「这把 key 在 X 上可用（N 个模型），
     在 Y 上被拒」，测试连接和真生成的失败卡都把这句话摆出来。
   - **测试结果留在弹窗里**（成功连上 + 模型数 + 耗时 / 失败的上游原话 + `GET /models` 的
     地址与状态码），而不是一闪而过的提示条 —— 这种要对着改的信息得站得住。
   真机实例：`gpt-image-2.5-c` 只存在 `api.velapi.cc` 目录里，而 GPT 供应商记录的 baseUrl 是
   `gank.velapi.cc`，那把 key 在那边 401；改成 `https://api.velapi.cc/v1` 后测试连接 61 个模型、
   真出一张 1254×1254 的图。
12. **结果卡只有图片是「卡」，动作只是文字**。生成的图下面原来有一条白底 + 上边框的动作条
   （「用这张重绘 / 复制链接 / 打开原图」），在 132~160px 的图片格里被挤成三行，
   看起来像又一张卡、还带分隔线。现在：图片自己一个圆角框（`.vig-shot-img`），
   下面三个动作**无底色、无边框、无分隔线**，并排一行；卡片窄，所以标签用短名
   （重绘 / 复制 / 原图，`data-short` 由 CSS 渲染），完整说法放在 `title` 里。
   四个宽度（600 / 320 / 160 / compact）真 Chrome 截图核对都是一行。
13. **查看器只负责「看」，动作复用现有链路**。结果卡 / 图库点开的是同一张图的全屏视图：
   滚轮缩放（20%–800%）、放大后拖拽平移、双击切「适应 / 100%」、`←/→` 在调用方给的列表里翻页、
   `Esc` 关。「用作参考图」读回字节后走和粘贴/上传同一条 `attachReference`（不另写一条上传路），
   「图片处理」把 dataUrl 交给 PsView 的 `initialUrl`，载入一次就回调清掉（来回切视图不会重复载入、
   也不会把后来的编辑顶掉）；「删除」只在图库来源给（聊天记录里的图不是图库条目）。
14. **快捷拖拽 = 一次拖起、四处可用**。拖动源（结果卡 / 图库卡片）在 `dragstart` 里同时写三种数据：
   自定义 `application/x-velapi-image`（URL / 名字 / assetId，接收端优先认）、`text/uri-list`
   （浏览器和「图片处理」的既有拖入路径）、`DownloadURL`（拖到资源管理器 = 落一份文件）。
   输入区 drop 先看自定义类型 → 读回字节 → 走 `attachReference`，不自建第二条上传链。
15. **素材目录默认本地、可搬家**。图库/上传/任务/供应商/预设/笔记/目录缓存全部挂在 `stateDir` 下。
   界面上改目录时宿主：校验可写 → 把现有文件**复制**到新目录（不覆盖同名、旧目录保留）→
   换整套路径 → 重新加载内存表；有在飞任务时拒绝（避免任务写旧目录、界面指新目录）。
   重启还记得靠**默认目录里的 `location.json` 指针** —— `config.json` 自己会跟着素材搬走，
   拿它当指针的话重启会先回默认目录读旧配置，改动就丢了。
   `POST /state/reveal` 负责在系统文件管理器里打开它（宿主在 Electron 主进程里，能 spawn）。
16. **结果图按张数自适应**。以前 `.vig-grid` 无条件 `auto-fill minmax(132px,1fr)`，单图也只拿到
   一个 132px 的格子 —— 生成出来一张大图，在对话里缩成一条。现在按张数挂
   `is-single / is-duo / is-trio` + `data-count`：单图 `minmax(0,50%)`（窄栏 62%）、两张各 36%、
   三张各 30%，四张起回到小格自动排。纯 CSS 网格（不量 JS、不挂 resize），compact 模式一套独立
   占比；真机量的宽度比：单图 ≈ 0.5、两张 ≈ 0.36。
17. **拖出去要落文件，不能只给一串文本**。页面跑在 `dsh-app://` 自定义协议下，资源管理器取不回
   这个 URL —— 之前 `DownloadURL` 里塞的就是它，拖到桌面只得到 `dsh-app://app/api/…` 文本。
   现在拖动前 `pointerdown` 先问宿主 `/asset/local`（图库原图的绝对路径 + `file://` URI，缓存在
   `LOCAL_FILE_CACHE`），`dragstart` 时若有就把它写进 `DownloadURL`；另带 `text/html`（`<img>`）
   给富文本目标。**但网页侧无法保证 OS 一定把拖拽当文件**（真正的原生拖拽要 Electron 主进程
   `webContents.startDrag`，插件客户端拿不到），所以同时提供可靠出口：`POST /asset/export` +
   查看器/结果卡/图库的「保存到本地」——宿主把原图复制进 `saveDir`（默认
   `%USERPROFILE%\Downloads\velapi-image-go`，同名落成 `-1`/`-2`），提示条报完整路径。
   `/asset/local` 必须注册在 `/asset/*` 静态路由**之前**，否则会被当成文件 "local" 直接 404。
   但**网页侧的 `DownloadURL` 终究只是「下载 URL」**，OS/目标程序未必把它当文件；实测拖到别的程序
   仍显示文本。要真文件只有一条路：Electron 主进程 `webContents.startDrag`。所以补了两条：
   - **每次拖都先试原生** → `dragstart` 里用**同步 XHR** 打 `POST /drag/native`（异步就赶不上这次
     手势），宿主找到焦点窗口调 `startDrag({file, icon})`，成功后 `preventDefault()` 压掉 HTML5
     拖拽；非 Electron 宿主回 501，客户端不 preventDefault，退回普通拖拽。同步请求有卡界面的风险，
     所以前面先 `GET /capabilities`（懒计算、按进程缓存）确认 `nativeDrag` 再发；老宿主 404 就
     保持 `HOST_CAPS = null`，永远不发同步请求（也不再要求用户按 Shift —— 按了反而更难发现）。
     老宿主 / 不支持原生拖拽时，头部挂胶囊明说（「宿主旧版本 · 重启 DSH 生效」/「拖出不可用 ·
     用复制图片」），而不是让用户以为拖拽坏了。
   - **兜底动作**：`POST /asset/export`（保存到本地，复制进 `saveDir`）与 `POST /clipboard/image`
     （Electron `clipboard.writeImage` 写系统剪贴板，PPT / 别的程序 Ctrl+V 直接贴图）；两条都在
     没有 Electron 时如实回 501，不假装成功。
18. **图生图是「上传文件」，不是「发 base64」**。`/images/edits` 沿用 OpenAI 那套契约：请求体必须是
   `multipart/form-data`，`image` 是文件字段（`model / prompt / n / size` 是普通字段），JSON + base64
   会被上游回 `400 image file or image_url is required`（用户截图就是这条）。所以三条一起改：
   - `callUpstream` 支持 `form`（有 form 就不带 `content-type`，交给 undici 自己写 boundary）；
     `/generate` 的 `mode=edit` 把 dataURL 解成 buffer → `Blob` → 表单文件字段（`reference.<ext>`）。
   - 只给 `referenceUrl`（本站 upload/asset）时，宿主从磁盘读回字节再发 —— 失败任务「重试」历史里
     只有缩略图 URL，靠这条才能真的重试图生图。
   - 协议选了编辑但没参考图 → 回落 `/images/generations`（`wantsEdits && requestImage` 才走 edits），
     不发注定 400 的请求；界面侧同样：挂参考图 + 选编辑协议就把 `mode: edit` + 字节带上。
   真上游 A/B：同一张参考图，JSON 版本 400（错误码 `bad_request`，消息与用户截图一致），
   multipart 版本 200 出图；再用本插件宿主的 `/generate` 端到端跑一次：`/images/edits` 200，
   62.7s 落盘 1254×1254。
19. **「把图给别人」不能只有拖拽一条路**。网页里的拖拽只能给 URL/文本，PPT 只认文件；
   原生拖拽要宿主重启且被沙箱限制时就没有出口。所以补两条不依赖原生拖拽的路：
   - **复制图片 = 图片位图，不是链接**。**宿主剪贴板优先**：`POST /clipboard/image` 里先试
     Electron `clipboard.writeImage`；实测 DSH 的插件宿主拿得到 `electron` 模块却拿不到它的 API
     （`/capabilities` 返回 `nativeDrag:false, clipboard:false`），于是再加一条 Windows 兜底：
     临时写一个 `.ps1`，`powershell -STA` 里 `System.Windows.Forms.Clipboard.SetImage` 把图位图写进
     剪贴板（本机验证 `ContainsImage()` 为真）。客户端只在宿主 `clipboard:false` 时才退到网页
     剪贴板（`ClipboardItem`），因为它经常写不进图片、还会留着上一次的 URL 文本（踩过：用户剪贴板
     历史里只有 `dsh-app://…` 文本）。`复制链接` 保持原义（URL 文本），两个按钮的 title 各自写明
     区别。
   - **下载文件 = blob + `<a download>`**：不依赖宿主端点（`dsh-app://` 的 `<a download>` 也不一定
     被接管），把图存进系统「下载」文件夹，从资源管理器拖进 PPT 是最稳的。
   这两条让「拖不出去」不再等于「拿不到图」。
20. **聊天流从上往下**。宿主 `/jobs` 和乐观插入都是「新的在前」，以前界面原样 `jobs.map()` ——
   最新一条排最上面，读起来是倒着的。现在 `.slice().reverse()`：老的在上、新的在下；新任务到来时
   自动滚到底，但用户往上翻历史（离底部 >160px）时不动滚动位置，不抢人。
21. **右侧检查器可折叠，但默认展开**。图片 / 预设卡 / 供应商那一列 268px，占得不少；加一个
   右上角「›」收起成 **34px 窄签**（竖排「图片 · 预设 · 供应商」+「‹」），点窄签展开。
   折叠状态进 `localStorage`（`dsh.velapi-image-go.side`，`"0"` = 收起），刷新后保持；
   `Inspector` 的 `open` / `onToggle` 都是可选 props —— 预览与测试照旧不带手柄渲染。
   窄形态（`data-compact="1"`）收起后改成横向窄条，避免在侧栏里挤成两行。
22. **常用动作先展开、管理动作才跳页**。输入框那颗便签图标原来直接跳「信息管理」页 ——
   想插一条提示词得先离开对话。现在一级是**就地浮层**：列标题 / 提示词摘要 / 标签，
   点一张走既有 `insertNote`（追加进草稿、500 字截断），收起浮层；二级「管理」才
   `setView("notes")`。空态给「去新建」，超过 20 张提示剩余数量。浮层点外面 / `Esc` 收起，
   展开态按钮高亮 —— 和模型下拉、图库选择同一套「先就地选，需要管理再跳」的交互。
23. **每条用户消息带三个就地动作**。以前要改一句话只能手动重打、要删记录只能翻后端。现在用户气泡
   下方三个**无底色纯 SVG** 图标按钮：重试（复用 `retryJob`，参数全部沿用）、删除（新端点
   `POST /job/delete`，只摘 jobs 不动图库；在队列/在飞的先 cancel 再摘，删前 `confirm`）、
   编辑（`editJob`：`userText || prompt` 填回草稿、连参考图一起挂上、按原 `mode` 决定是否编辑态）。
   行本身只在有回调时渲染（预览/测试不会多出一个空 div）。
24. **尺寸下拉把比例和分辨率一起摆出来**。上游要像素、用户想比例，所以选项表把「比例 → 像素」
   写死成 `1:1 1024×1024 / 3:2 1536×1024 / 2:3 1024×1536 / 16:9 1536×864 / 9:16 864×1536 /
   21:9 2048×864 / 2K 两档`；**正面文案是 `16:9 · 1536×864`**（比例 + 分辨率一起给，不藏进
   `title` —— 只给比例那次用户直接问「分辨率哪去了」）。一行放不下就按 `flex-wrap` 换行，
   不截断信息；选中仍写 `config.defaultSize` 的像素值（发给上游不变）。老配置里不在表里的尺寸
   补一条「自定义」，避免下拉变空。
25. **对话（会话）= 一段独立记忆**。`conversations.json` 存会话（id / 标题 / 时间），任务记录带
   `conversationId`；老任务没有这个字段就在启动时归到 `conv_default`（迁移一次落盘）。
   头部下拉切换会话并按 `conversationId` 拉 `/jobs`；`+` 新建（**不带上一段记忆**）、`✎` 改名、
   `🗑` 删除（连带删该会话任务，图库不动）。`/generate` 收到不存在的会话 id 时落默认会话，
   不把任务丢进黑洞；新任务会更新会话 `updatedAt`，自动标题（新对话 N / 默认对话）用第一句提示词命名。
26. **上下文管理交给一个对话模型**（用户原话：「让一个多模态模型接消息并生图，本地记忆 + 控制上下文
   风格/联系」）。`POST /chat/plan` 把**本会话**最近 `contextTurns` 轮（用户原话 / 实际提示词 / 结果图
   URL）+ 这次这句话 + 目标模型/尺寸/参考图交给 `chat/completions`，系统提示要求它只回
   `{prompt, mode, referenceUrl, reason}`；容错剥 ```json 围栏、抠首个 `{…}`、`prompt` 为空即判定失败。
   客户端：默认开启（可关），生成前先 plan；气泡保留**用户原话**（`job.userText`），改写结果进
   `job.planNote` 单独一行；`mode: edit` + `referenceUrl` 时宿主按 URL 读回字节走 multipart 编辑。
   plan 失败/无对话模型 → 按原话生成，绝不阻断。会话隔离是这套东西的前提：history 只取当前会话
   的 jobs，新对话没有历史，风格/指代不会串场。
   **意图分类（action 三态）**：`generate / edit / reply` —— 用户在纠正/抱怨/提问时判成 reply
   （只回一句话、不出图），并把「不得凭空新增主体」「纠正优先」写进系统提示（踩过：纠正

   `POST /chat/message` 存进会话历史（`kind: reply`，气泡直接显示这句话）。

   chip 单张可移除；请求带 `images[]` + `referenceUrls[]`（老单数字段兼容），图生图 multipart
   每张一个 `image` 字段；plan 提示词列出「第 1…N 张」的完整清单，指代纠正不再只看一张。

## 开放接口与过程留痕

生图这件事只有一条链路：**入队 → 打上游 → 落盘 → 入库**。三张嘴都通向它，区别只在
`source` 这一个字段：

| 入口 | 谁在用 | 怎么进来 | `source` |
| --- | --- | --- | --- |
| 工作台 | 人 | 输入框 → `POST /generate` | `ui` |
| DSH 工具 | 对话里的模型 | `generate_image`（`ctx.tools.register`） | `tool` |
| HTTP | 外部程序 / 脚本 | `POST /api/velapi-image-go/generate` | 缺省 `api` |

三处设计取舍：

1. **工具不是第二条实现**。`generate_image` 的 `execute()` 直接复用同一套队列（`enqueue`），
   然后**等它跑到终态**再回结果 —— 工具调用要么拿到图，要么拿到原因（`ok: false` + 上游原话 +
   `errorCode`），不返回一个「你自己再去轮询」的 task id。等多久有上限：`max(30s, timeoutMs+15s)`。
2. **注册状态对外可见**。「工具到底装上没有」不能靠猜：`/status.tool` 给
   `{name, registered, reason}`，失败原因写具体（宿主没有 `tools` 服务 / 解析不到
   `@deepseek-ai/dsh-tools` 的 `defineTool` / 注册抛的原文）。`defineTool` 从这个包外面
   解析不到（插件目录不在宿主 node_modules 里），所以按
   `app.asar/dsh/node_modules` → `app.asar/node_modules` → `app/node_modules` 顺序动态查找。
3. **过程跟素材写在同一张纸上**。任务（`jobs.json`）记 `prompt / revisedPrompt / model / size /
   quality / count / protocol / endpoint / source / sessionId / elapsedMs / errorDetail`；
   素材（`library.json`）除了 `sha256` / 尺寸 / `remoteUrl`，同样带
   `prompt / model / size / quality / jobId / source / sessionId`。这样「这张图是哪句话生的、
   走的哪条协议、是界面点的还是对话里调的」直接在图库里反查得到，不需要另存一份日志。
   参考图的 base64 照旧只在这一次请求里活着，任务落历史时已经删掉，只留 URL。

界面上这一项的体现很小：对话记录里每条回复多一行 `来源 · 工作台 / 工具调用 / 外部接口`
（带 `会话 <id>`）；老记录没有 `source` 就**不显示**，不瞎猜一个。
