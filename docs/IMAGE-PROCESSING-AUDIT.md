# 图片处理：文档、图层与像素输出审计

基线：本地提交 `063d209`。范围是「图片处理」页以及查看器向它交接图片的入口；不包括供应商、生图模型、服务端存储迁移或项目文件格式。此次为日常修复，不递增包版本。

## 编辑器现在以什么为准

```text
文件 / 拖放 / 图库 / 查看器 → 读取意图 → 解码和 DPI → 当前文档（底图 + 图层 + 元数据）
                                              ↓
工具参数、选区、拖点 → 显式执行 → 新像素 / 图层事务 → 历史快照
                                              ↓
                                 已提交合成 → 显示 / PNG / 参考图 / 切块
```

- **交接与解码**：在用户发起操作时分配读取所有权，而不是解码完成时决定归属。新读取中止旧请求；即使传输忽略中止，也不允许旧成功、异常或 `finally` 更新状态。解码失败保留已有文档。文件和响应体通过临时 Blob URL 解码，读取 DPI 只取前 256 KiB；成功、失败和取消均释放该 URL。桌面图片使用已有受限的 `dsh-app://app` 素材路由。
- **文档与历史**：底部图层条与右侧面板使用相同的修改入口。新增、删除、排序、蒙版、混合模式、显隐和透明度只在确实变化时入历史；一次拖动透明度只入一步。快照共享已提交画布引用，不在每次点控件时拷贝整张图；像素变换产生新画布。时间线按「过去 → 当前 → 未来」寻址，分支编辑清空旧重做。普通单层编辑使用局部历史，退出时只把实际改动合并为文档的一步。
- **草稿与输出**：未确认的取点、选框和工具参数不能作为导出输入。普通文档读可见合成；单层会话读该层原尺寸像素。几何操作分别变换底图、图层与蒙版，避免先压平再变换一次图层。反相、曲线、色阶、滤镜、羽化或切块不能只读底图。完整的普通模式效果层保留透明结果；蒙版外仍显示下层，透明度控制结果的混合强度。

## 图片的九点变换与矩形选区

图片边框上的九个手柄改变**当前图片**，不是只调整选区：拖四角同时调整宽高，拖四边中点只调整对应方向，拖中心移动。拖角时按住 Shift 可锁定比例。拖动过程中按 Esc 取消；松开提交后，可撤销或重做这一次变换。原有框选、四点透视是不同的操作。

**自由变换和蒙版的区别**：自由变换会重新采样图片；把右边点向右拉过原画布边界时，新增加的区域应当出现拉伸后的图片像素，下载的 PNG 也应包含这部分。矩形蒙版则只改变哪些像素可见：收窄边界不会把图案压扁，向外扩大也不会凭空补出内容。

旧版 `v0.2.100.106` 的复现条件：25% 缩放，将 96×64 不透明图的右缘拉到 x=160。蓝框超出画面 16 CSS 像素，而下载仍为 96×64，x=144 不在输出中。回归要检查扩展区的颜色和 PNG 尺寸，不能只检查蓝框位置。

浏览器复验：`node tools/viewer-check.mjs --query audit=pstransform` 和 `node tools/viewer-check.mjs --query audit=psoverflow`。

## 只点击「图片处理」、不打开任何图片

这条路径与下节不同：工作台已启动，只从「对话生图」点导航，没有传入文件或编辑文档。[空页导航专项](../test/ps-entry-perf.test.mjs) 用真实 Workbench、200 条合成图库记录、12 张预设和本地 HTTP 服务，在切页前重置素材请求计数。旧版 `88d9869` 直接将原图 URL 填入 24 张最近生成和 12 张预设的 `<img>`；即便 `loading="lazy"`，在测试视口、550ms 的观察期内仍实收 27 次原生图片 GET。只拦截 JavaScript `fetch` 会漏算这批请求。

新版首屏只有上传、选图与折叠入口，不挂载图片区；相同条件下是 0 个图片节点、0 次素材 GET。用户展开后每批 8 张，通过图库的可见性判断、缓存和两个并发槽加载缩略图。从图库弹窗也复用同一队列。选定图片才把该记录的原图交给编辑器；未提供预制缩略图时，展开的可见卡片可以读取原图制作预览。此处衡量的是进入页面时移除的图片工作，不代表所有设备的点击耗时。

```powershell
npm run test:ps-entry-perf -- --before  # 读取 88d9869，不切换工作树
npm run test:ps-entry-perf
```

## 首次打开大图的缓冲预算

打开卡顿的热点是编辑器把屏幕预览和空选区覆盖层都分配成原图大小。8K 8192×3456 的两张额外 RGBA backing store 估算 **216 MiB**，即使预览实际只有 627×264 CSS 像素。现在适应屏幕后，主预览以不超过 2×设备 DPR 绘制，空闲覆盖层为 1×1；选区/标尺/透视草稿出现时，覆盖层再按预览尺寸创建。源画布仍保留完整 8K 像素，切块、导出、滤镜和几何编辑继续使用原尺寸。

本机 Chrome、同一合成 8K PNG（以本地 data URL 输入，**不计网络传输**），在空闲环境 A/B 测得：旧 `9d0264a` 首帧可读 **446ms**、显示 backing store **216 MiB**；当前版首帧 **284ms**、显示缓冲约 **0.6 MiB**。该轮首帧约快 **36%**，显示缓冲少约 **99.7%**。毫秒值会受系统负载影响；实时基准重复值在 284–343ms，脚本只硬断言分辨率/缓冲边界，不把毫秒作为 CI 门槛。解码后的原始文档仍约 **108 MiB RGBA**，这项源数据内存并未消失。

```powershell
node test/ps-open-perf.test.mjs --before
node test/ps-open-perf.test.mjs
npm run test:ps-open-perf
```

`--before` 从 Git 读取旧版源码，仅加载到一次性测试页，不切换工作树。8K 测试只生成合成 PNG，不访问用户图库或供应商。
